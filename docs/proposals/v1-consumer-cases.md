# V1 installed-consumer cases

Status: authored and unrun. These two profiles cover the newly specialized
sixteen-component surface and fourteen-module copied-source closure. They do
not rerun the accepted 52-case or prior installed-consumer packets. The new
family schema/SSR cases and browser interactions remain separate checks.

`tooling/v1-installed-consumer.mjs` runs only in the approved Linux CI packet,
on Node 24.22.2. Its 300-second total allowance includes a 290-second work
window and ten seconds for child closure/reporting. The outer controller must
admit that complete allowance before launch and owns final process-namespace
inspection and scratch removal. This helper never recursively removes work.

## Profiles

1. **C01-package** installs seven actual reviewed pnpm archives as direct local
   `file:` dependencies: core, schemas, runtime, React, themes, registry and
   the `mcpcn` CLI. Archive names/versions come from source manifests and must
   match the parent-produced archive manifest and actual bytes/SHA-256/SHA-512.
   Every MCPCN dependency must resolve to exactly one root installed archive;
   nested duplicates, registry substitutions or changed installed `dist`
   bodies fail. The actual installed `.bin/mcpcn` launcher initializes package
   mode and installs all 79 entries. An installed-module probe verifies sixteen
   function exports, eleven implementations distinct from the generic alias,
   sixteen actual named schemas and the registry's public JSON Schema getter.
   It also binds the public fourteen-path source-module inventory and renders
   the configured providers through the actual installed registry helper.
2. **C02-copy** creates a separate consumer with only the external dependencies.
   It invokes that same installed CLI launcher with the new consumer's cwd,
   selects the freshly generated local file registry and copies all 79 entries.
   The ownership manifest must enumerate the exact selected items and complete
   file closures, including fourteen real shared modules, blocks, provider,
   styles and license. Every copied byte must match its registry payload,
   apart from the provider generated for the explicit host/theme choices.
   The provider must exactly match the installed helper's configured output.
   No copied TS/TSX source may import an `@mcpcn/` package, and the copy consumer
   must contain no installed MCPCN packages.

Both consumers preserve an authored unrelated marker and compile all installed
entry wrappers/provider and explicit references to all sixteen public component
and `NamedData` exports. Each runs its own installed TypeScript 5.9.3 with
`strict: true`, `noEmit: true` and `skipLibCheck: false`. The new fixture includes
an authored confirmation JSX use; no additional component SSR, host connection,
model call or business operation is executed.

The fixed external profile reuses React/ReactDOM 19.2.8, Zod 4.4.3, ext-apps
1.7.5, MCP SDK 1.30.0, TypeScript 5.9.3 and React/ReactDOM types
19.2.18/19.2.4. Installs disable lifecycle scripts, audit, funding and package
manager retries. Fresh transitive npm locks and actual installed trees are
retained; they are not claimed equivalent to the workspace's pnpm graph.

## Owned inputs and evidence

The controller forwards `SOURCE_COMMIT`, `MCPCN_V1_RUN_ROOT`,
`MCPCN_V1_NONCE`, `MCPCN_V1_SOURCE_ROOT`, `MCPCN_V1_ARCHIVES`,
`MCPCN_V1_ARCHIVE_MANIFEST`, `MCPCN_V1_OUTPUT` and `MCPCN_V1_WORK`.
The physical private root has `.owner` containing the exact 32-hex nonce.
`source`, `archives`, `output` and initially empty `consumers` are its fixed
children. The helper preserves original HOME and permits only the pinned Node
bin and system directories on PATH. Child configuration, caches and temporary
paths must already be owned physical paths under that root; no inherited
credentials, proxy settings, preloads or user npm configuration are forwarded.

The helper writes exactly `output/consumers.json`, with schema version 1,
checked source, ordered C01/C02 statuses, actual command argv/exits and bounded
original stdout/stderr. Every stream has gzip/base64, complete byte count,
SHA-256, observed digest and EOF/descriptor observations. Source/archive and
archive-manifest identities/hashes are compared before and after work.
Consumer locks, ownership/configuration/fixture originals, installed trees,
package body vectors and compiler-entry identities remain independently
auditable in that receipt. Originals are attached before their acceptance
gates; failure never turns an unvisited profile into a pass.

Streams are capped at 128 KiB each; accumulated retained base64 is capped at
1 MiB with the crossing original attached before refusal. The final receipt is
capped at 4 MiB. Successful collection requires both cases, complete original
streams, normal zero exits, reaped children, absent original process groups,
no signals and unchanged inputs. Timeouts or uncertain closure remain failed.
The helper retains its work for the controller's guarded final cleanup.

These are archive/source-installed consumer observations, not public npm
availability, npm ownership/publication, native browser accessibility, live MCP
host interoperability or whole-library behavioral acceptance. No local
installation, build, execution or generation is authorized by this proposal.
