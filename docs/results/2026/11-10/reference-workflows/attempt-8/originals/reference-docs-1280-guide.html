Working examples

Review a real change. Keep its audit.

Five reference applications connect React review surfaces to actual MCP tools and a persistent private SQLite workspace. Inspect supplied evidence,correct fields,review an order,change a reference preference or save a research decision.

Run locally

Use Node 24.22.2 and pnpm 10.24.0 on macOS or Linux. Clone the repository,or download the focused workbench source and extract it. From its root:

pnpm install --frozen-lockfile --ignore-scripts
pnpm examples:build
pnpm examples:dev --workspace /absolute/private/reference-workspace

Choose an empty private directory or a recognized reference workspace you own. Open the printed loopback address and enter the per-launch access code. Keep the listener local and the code private. Press Ctrl-C to close it; use the same workspace path to reopen saved records and audit events.

Review and confirm

  1. Open a server record and inspect its complete supplied data.
  2. Propose a decision or correction. The server prepares exact terms against the current revision.
  3. Review the before/after values and check a fresh acknowledgement. Confirmation persists the change and its audit atomically.
  4. Reload the record to verify its actual saved state. Cancelled,expired or stale reviews cannot apply a change.

Checkout records an uncharged local order,with server-owned prices,shipping,tax,return terms and a reviewed quote-refresh path. Settings rollback also requires a fresh review. Document extraction accepts explicitly submitted UTF-8 invoice,contract or resume text; its literal-line matches are not OCR or a model interpretation. Research gathers configured primary sources,retains partial failures,retries only the selected failed source and saves your own final decision.

Access and data boundaries

The workbench uses real Client/McpServer and official AppBridge/OfficialMCPAdapter traffic. It derives a trusted local principal from the selected private workspace and OS operator. Host/Origin checks,a per-launch capability and a short-lived HttpOnly SameSite cookie protect local requests. It serves trusted built-in apps; its iframe is not a sandbox for arbitrary third-party HTML.

Only deliberate identifiers,status and receipts are model-visible. Full source text,addresses,notes and prepared tokens use explicit app metadata,which remains visible to the host. Metadata,visibility and a consent checkbox do not authenticate a user or prove human identity. Public or multi-user deployments must supply verified transport authentication.

No card is charged,no candidate is contacted,and no SSO,email,OCR or AI provider is configured. These are persistent local reference workflows. Production identity/providers,external-host compatibility,Windows and full accessibility/device acceptance remain separate. A failed network response can follow a completed mutation: reload and inspect the saved audit before trying another action.
